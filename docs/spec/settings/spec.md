# 设置页面（服务器连接 · 账号 · 分类维度）

让用户在设置页完成三件事：连接自己的同步服务器、登录账号、定义四个分类维度的取值。设置页的视觉与交互参照 `docs/assets/settings.html`（前端由他人负责实现）；本 spec 同时约束页面行为与背后服务的对外行为，全部从用户可感知的角度描述。书签数据同步本体不在本 spec 范围（属于下一阶段），本页只涉及「连接与账号」及「分类取值」的保存与一致。

## feat01: 测试服务器连接

用户填入自己的同步服务器地址后，可以先确认这台服务器是否可用，再决定登录。

场景1: 连接成功

- GIVEN 设置页已打开，服务器地址与端口已填写，对应服务正在运行
- WHEN 用户点击「测试连接」
- THEN 按钮短暂显示连接中状态，随后显示「连接成功」，并展示本次往返延迟与服务版本号

场景2: 地址未填完整

- GIVEN 服务器地址或端口为空
- WHEN 用户点击「测试连接」
- THEN 显示「连接失败」，并提示「请先填写服务器地址与端口」

场景3: 服务器不可达

- GIVEN 服务器地址指向一台不存在或未启动的服务
- WHEN 用户点击「测试连接」
- THEN 显示「连接失败」，并提示无法访问或连接超时；不改变当前登录状态

## feat02: 管理历史服务器

用户用过的服务器会被记住，之后可以一键切换，不用重复输入。

场景1: 登录成功后自动记录

- GIVEN 用户在某台服务器上登录成功
- WHEN 登录完成
- THEN 该服务器出现在「历史服务器」列表最上方并标记「当前」，同时记录本次登录时间

场景2: 切换到历史服务器

- GIVEN 历史列表中有多台服务器
- WHEN 用户点击其中一条（单选圆点或地址文字）
- THEN 该条成为当前服务器，地址与端口栏同步更新为该服务器，并自动执行一次连接测试、显示测试结果

场景3: 修改历史记录

- GIVEN 历史列表中有一条记录
- WHEN 用户点「修改」，改写地址或端口后点「保存」
- THEN 该条记录更新为新地址；若修改的是当前服务器，地址栏内容一并更新

场景4: 删除历史记录

- GIVEN 历史列表中有一条非当前服务器
- WHEN 用户点「删除」
- THEN 该条从列表移除；若删除的是当前服务器，地址栏保留其内容不变

场景5: 没有任何记录

- GIVEN 用户从未成功登录过任何服务器
- WHEN 打开设置页
- THEN 历史区域显示「暂无记录，登录成功后自动保存。」

## feat03: 登录账号

用户用邮箱和密码登录自己的同步服务器，登录后开启同步能力。

场景1: 登录成功

- GIVEN 服务器连接正常，用户已注册账号（账号由服务器管理员预先创建）
- WHEN 用户输入正确的邮箱和密码，点击「登录」
- THEN 登录表单隐藏，显示登录状态卡片：头像字母、邮箱、「上次同步」信息；卡片头部状态变为「已登录 · 同步开启」

场景2: 邮箱或密码错误

- GIVEN 服务器连接正常
- WHEN 用户输入了错误的邮箱或密码
- THEN 提示「邮箱或密码不正确」，停留在登录表单，已输入的邮箱保留

场景3: 服务器不可用

- GIVEN 服务器地址不可达或未填
- WHEN 用户点击「登录」
- THEN 提示连接失败、请先检查服务器地址，不进入登录中状态

场景4: 再次打开设置页时保持登录

- GIVEN 用户之前已登录且未退出
- WHEN 重新打开设置页
- THEN 直接显示登录状态卡片，不要求重新输入密码

场景5: 注册入口

- GIVEN 用户未登录
- WHEN 用户打开登录表单
- THEN 登录按钮旁出现「创建账号」入口，点击弹出创建账号表单（见 feat09）；账号仍可由服务器管理员通过命令行创建

## feat04: 退出登录

用户可以退出当前账号，回到未登录状态。

场景1: 退出

- GIVEN 用户已登录
- WHEN 点击登录状态卡片中的「退出登录」
- THEN 回到登录表单，状态显示「未登录」；下次打开设置页需要重新登录；本机已保存的书签不受任何影响

## feat05: 查看四个分类维度

用户打开设置页就能看到四个分类维度各自的取值集合，知道每个维度回答什么问题。

场景1: 首次使用展示默认取值

- GIVEN 全新安装，用户从未修改过分类取值
- WHEN 打开设置页的「分类维度」卡片
- THEN 四个维度分别展示一组默认取值：主题（AI、Harness、世界模型、上下文工程）、形态（博客文章、GitHub 仓库、论文、文档）、用途（学习原理、项目参考、工具备用）、状态（Inbox、Reading、Done）

场景2: 维度说明

- GIVEN 分类维度卡片展示中
- WHEN 用户浏览四个维度
- THEN 每个维度显示名称与它回答的问题（主题=它讲什么、形态=它是什么、用途=我拿它干什么、状态=我处理到哪了）；主题/形态/用途标注「多选」，状态标注「单选」（状态取值之间没有先后流转关系，就是一组只能单选的标签）

## feat06: 新增维度取值

用户可以为任意维度添加自己想要的取值。

场景1: 添加成功

- GIVEN 用户在某个维度的取值列表中
- WHEN 在输入框输入新取值后按回车或点「＋」
- THEN 该取值以标签形式出现在此维度列表末尾，输入框清空可继续输入

场景2: 空输入

- GIVEN 输入框内容为空或只有空格
- WHEN 按回车或点「＋」
- THEN 不添加任何取值

场景3: 重复取值

- GIVEN 该维度已存在取值「AI」
- WHEN 再次输入「AI」提交
- THEN 提示「该取值已存在」，不产生重复标签

场景4: 输入整理

- GIVEN 用户输入「&nbsp;学习&nbsp;」（首尾带空格）
- WHEN 提交
- THEN 保存为「学习」（自动去除首尾空格）；若取值超长（超过 30 字），提示「取值过长」并不保存

场景5: 未登录时添加

- GIVEN 用户未登录，仅本机使用
- WHEN 添加取值成功
- THEN 取值保存在本机并立即生效；待用户登录后自动上传到服务器

## feat07: 删除维度取值

用户可以删掉不再使用的取值，书签本身不受影响。

场景1: 删除成功

- GIVEN 某维度有多个取值
- WHEN 用户点击某取值标签上的「×」
- THEN 该取值从列表中消失

场景2: 书签不受影响

- GIVEN 有 3 条书签被标了主题「Harness」，且 Harness 是主题维度的一个取值
- WHEN 用户删除取值「Harness」
- THEN 这 3 条书签的网址、标题、摘要、备注完全不变；「Harness」不再出现在筛选候选中；用户编辑这些书签的属性时，旧的「Harness」标记自然消失（不会被主动清除，也不产生报错）

场景3: 默认状态不可删除

- GIVEN 状态维度存在系统默认取值「Inbox」
- WHEN 用户点击「Inbox」上的「×」
- THEN 不删除，提示「默认状态不可删除」

场景4: 新收藏永远有默认状态

- GIVEN 用户使用任意状态取值组合
- WHEN 新收藏任何网页
- THEN 该书签的状态永远默认为「Inbox」；不存在「未设置」的状态——「Inbox」作为系统默认值始终保留在状态维度中，其余状态取值（如 Reading、Done）可自由删除

## feat08: 分类取值多设备一致

登录后，用户在一台设备上对分类取值的任何修改（增、删、排序）会同步到服务器，其他设备保持一致。

场景1: 修改上传

- GIVEN 用户已登录
- WHEN 用户在任一维度新增或删除取值
- THEN 修改保存到服务器；另一台设备随后登录时，看到相同的取值集合

场景2: 首次登录取得服务器版本

- GIVEN 用户在本机未登录时改过取值，服务器上也有该账号的历史取值
- WHEN 本机登录成功
- THEN 以最后修改的一版为准（本机与服务器的取值内容按修改时间新者胜出），无需用户手动合并

场景3: 两台设备先后修改

- GIVEN 两台设备都登录着同一账号，且都离线修改了取值
- WHEN 两台设备先后恢复连接
- THEN 以修改时间较晚的一版为准，覆盖较早的一版；不弹出冲突提示，用户在设置页看到的是最终保留的那一版

## feat09: 创建账号

用户无需麻烦服务器管理员，自己在设置页就能创建账号，创建完成直接进入已登录状态。

场景1: 创建成功并自动登录

- GIVEN 服务器连接正常，输入的邮箱尚未注册
- WHEN 用户在创建账号弹窗中输入有效邮箱与合规密码，点击「创建」
- THEN 弹窗关闭，直接显示登录状态卡片（与登录成功相同）；该账号已保存在服务器，之后可用同一邮箱密码登录

场景2: 密码不合规

- GIVEN 创建账号弹窗已打开
- WHEN 用户输入的密码不含英文、或不含数字、或长度不超过 5 位
- THEN 提示「密码需包含英文和数字，且大于 5 位」，停留在弹窗中，不向服务器发送请求

场景3: 邮箱已被注册

- GIVEN 输入的邮箱已在服务器注册过
- WHEN 用户点击「创建」
- THEN 提示「该邮箱已注册」，停留在弹窗中，已输入的邮箱保留

场景4: 服务器不可用

- GIVEN 服务器地址不可达或未填
- WHEN 用户点击「创建」
- THEN 提示连接失败、请先检查服务器地址，停留在弹窗中

场景5: 邮箱格式非法

- GIVEN 创建账号弹窗已打开
- WHEN 用户输入的不是合法邮箱地址
- THEN 提示「请输入有效的邮箱」，停留在弹窗中，不向服务器发送请求

## feat10: 手动同步收藏

已登录用户可以随时点一下，把本机收藏与服务器对齐，并看到这次同步给本机带来了哪些变化。

场景1: 同步成功并显示变更计数

- GIVEN 用户已登录，服务器连接正常
- WHEN 用户点击登录状态卡片中的「同步收藏」
- THEN 按钮显示同步中状态且位置不跳变（宽度固定）；完成后「上次同步」时间刷新，按钮下方显示本次同步计数：使本机发生的新增（绿色）、删除（红色）、修改（中性色），以及上传到服务器的本机变更条数「上传 N」；若双向都无变化则显示「本次同步无变更」

场景2: 服务器不可用

- GIVEN 服务器地址不可达
- WHEN 用户点击「同步收藏」
- THEN 提示「同步失败，请检查服务器地址或稍后重试」，不改变「上次同步」时间，不影响本机数据

场景3: 登录已过期

- GIVEN 用户登录态已失效（服务器拒绝）
- WHEN 用户点击「同步收藏」
- THEN 提示登录已过期并回到登录表单，本机书签不受影响

场景4: 未登录

- GIVEN 用户未登录
- WHEN 打开设置页
- THEN 不出现「同步收藏」按钮（它只在登录状态卡片中）

场景5: 同步范围

- GIVEN 用户已登录
- WHEN 执行一次同步（手动或自动）
- THEN 收藏书签与四个分类维度的取值都与服务器对齐（冲突以修改时间较新的一方为准）；本机没有的远端新增进入本机，远端删除的本机同步删除

## feat11: 自动同步开关

用户可以为每个账号单独决定是否让收藏变更后自动同步，不用每次都手动点。

场景1: 开启后变更即时同步

- GIVEN 用户已登录并勾选「自动同步」
- WHEN 本机发生收藏或分类取值变更（导入、收藏、编辑属性、删除取值等）
- THEN 稍候片刻自动执行一次同步，无需手动点击

场景2: 关闭后不自动同步

- GIVEN 用户未勾选「自动同步」
- WHEN 本机发生收藏变更
- THEN 不发起任何同步，只有手动点「同步收藏」才同步

场景3: 开关跟随账号

- GIVEN 用户在账号 A 勾选了「自动同步」，在账号 B 未勾选
- WHEN 先后登录账号 A 与账号 B
- THEN 登录 A 时开关显示勾选，登录 B 时显示未勾选；两个账号的偏好互不影响

场景4: 默认关闭

- GIVEN 某账号从未设置过该开关
- WHEN 登录该账号
- THEN 「自动同步」默认未勾选

场景5: 收藏后面板立即关闭也会完成同步

- GIVEN 用户已登录并勾选「自动同步」
- WHEN 用户在收藏面板保存一条收藏，面板随即关闭
- THEN 这次同步仍会在后台完成（自动同步不依赖任何页面保持打开）
