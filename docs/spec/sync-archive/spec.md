# 同步状态与快照存档（云朵标记 · 汇总 · 按账号存档）

让用户在收藏页一眼看出「我的东西是否已经安全存到当前账号的服务器上」：每张卡片有低干扰的云朵同步标记，页头有整库汇总，出问题时能一键筛出还没同步的收藏。同时提供快照存档：把整库一键存成带时间的快照、归到当前登录账号名下，需要时整库恢复。本 spec 建立在《设置页面》feat10/feat11（手动同步、自动同步）之上，只描述用户可感知的行为。一次只有一个登录账号（不是并行维护多个账号）：服务器按账号各存一份收藏；本机为每个登录过的账号各留一份独立的本地收藏库，未登录时使用全局唯一的默认收藏库（default，无账号归属、能收藏、不同步）——界面与同步永远只作用于当前那一份库，登录、登出、切换都只是换库，各库互不混入、不删除数据，默认库与账号库之间互不流动。

## feat01: 默认收藏库与账号收藏库

未登录时使用全局唯一的默认收藏库（default）：收藏、导入、筛选、搜索照常可用，无账号归属、不参与同步，界面上不出现任何同步功能（云朵标记、同步汇总、待同步筛选、快照存档）。登录后使用该账号专属的本地收藏库（本机没有就从云端取来）；本机为每个登录过的账号各留一份库，切换账号即换库。各库互不混入，切换与登出都不删除数据，默认收藏库与账号收藏库之间互不流动。

场景1: 未登录使用默认收藏库

- GIVEN 全新安装，未登录任何账号
- WHEN 用户收藏或导入书签
- THEN 收藏保存在默认收藏库中，主页浏览、搜索、四维筛选照常可用；界面上不出现任何同步相关的功能

场景2: 登录即使用账号专属库，默认库不受影响

- GIVEN 默认收藏库里有 20 条，用户登录账号 A（A 云端有 80 条）
- WHEN 登录完成
- THEN 界面切换为账号 A 的收藏库（含从云端取来的 80 条）；默认收藏库仍保留那 20 条，原样不动、不并入 A

场景3: 切换到另一账号，各看各的库

- GIVEN 本机有账号 A 的库（150 条，已同步），账号 B 云端有 80 条
- WHEN 用户在已登录 A 的状态下直接登录 B 并确认切换
- THEN 当前登录状态变为 B（A 自动退出），本机列表与分类维度取值都换成 B 的内容（80 条、B 的取值清单）；A 的 150 条留在 A 的云端和本机 A 的库里，不会进入 B

场景4: 切换不丢旧账号的未同步改动

- GIVEN 本机账号 A 的库里有 2 条还没推送到云端
- WHEN 用户切换到账号 B
- THEN 切换立即完成；这 2 条既不进入 B、也不被删除，仍留在本机 A 的库里，下次登录 A 时自动补推

场景5: 切回原账号完整恢复

- GIVEN 用户曾在账号 A 下使用（本机留有 A 的库）
- WHEN 重新登录 A 并同步
- THEN A 的库回到本机界面，包括云端在用户离开期间新增的更新和本地未补推的改动

场景6: 离线也能切回用过的账号

- GIVEN 本机留有账号 A 与账号 B 的库，当前在 B，服务器无法访问
- WHEN 用户切换回 A
- THEN 界面显示 A 的库，收藏照常可用（离线优先）；待同步的改动联网后补推

场景7: 切换到本机没用过的账号需要联网

- GIVEN 本机有账号 A 的库，但没有账号 B 的库（B 在云端有 80 条）
- WHEN 服务器无法访问时用户尝试切换到 B
- THEN 提示「需要联网获取账号 B 的收藏」，切换暂停

场景8: 退出登录回到默认收藏库

- GIVEN 用户在账号 A 下使用（A 的库有 150 条）
- WHEN 用户退出登录
- THEN 界面回到全局唯一的默认收藏库，显示其中的内容（若为空则显示空态与登录提示）；A 的库留在本机与云端，再次登录 A 完整回来

场景9: 登出期间的收藏只进默认库，不跟任何账号走

- GIVEN 用户退出登录后在默认收藏库里收藏了 10 条
- WHEN 用户之后登录账号 B
- THEN 这 10 条仍留在默认收藏库中，不进入 B；界面显示的是 B 自己的库

## feat02: 已删除的收藏不再出现

某条收藏在服务器上被删除后，同步过的设备不会再显示它，条数统计也不把它算进去。

场景1: 同步带入删除

- GIVEN 本机收藏库有「某文章」，服务器上这条收藏已被删除
- WHEN 用户点击「同步收藏」
- THEN 该收藏从本机的收藏列表和条数统计中消失

场景2: 删除后重新收藏

- GIVEN 某条收藏的删除已同步到本机
- WHEN 用户重新收藏同一个页面
- THEN 它重新出现在收藏列表中，收藏时间按这次重新收藏的时间记录（删除后不保留原收藏时间）

场景3: 未知收藏的删除记录

- GIVEN 服务器上有一条删除记录，但本机当前收藏库里没有这条收藏
- WHEN 同步完成
- THEN 本机无任何变化，也不报错

## feat03: 收藏卡片显示云朵同步标记

每张收藏卡片用一枚云朵标记显示这一条的同步状态：已同步时低调存在，待同步时醒目提醒。

场景1: 已同步的收藏

- GIVEN 用户已登录，某条收藏自上次成功同步后没有再改动
- WHEN 用户查看收藏卡片
- THEN 卡片来源信息行（域名 · 时间）末尾显示一枚低对比度的云朵标记，鼠标悬停显示「已同步 · <账号邮箱>」

场景2: 待同步的收藏

- GIVEN 用户已登录，某条收藏刚收藏或刚修改，还没有同步上去
- WHEN 用户查看收藏卡片
- THEN 这条卡片的云朵标记以醒目的待同步样式显示，与已同步样式明显区分

场景3: 自动同步完成后状态翻转

- GIVEN 某卡片云朵处于待同步样式，且该账号的自动同步已开启
- WHEN 自动同步在后台完成，用户没有刷新页面
- THEN 云朵变为已同步样式

场景4: 未登录时不显示

- GIVEN 用户未登录任何账号
- WHEN 用户查看收藏卡片
- THEN 卡片上不出现任何同步标记

场景5: 同步失败不误报

- GIVEN 存在待同步的收藏，本次同步因服务器无法访问而失败
- WHEN 用户查看收藏卡片
- THEN 云朵保持待同步样式，不显示成已同步

## feat04: 收藏页汇总行

收藏页页头用一行小字告诉用户整库的同步情况。

场景1: 已登录且全部同步

- GIVEN 已登录，152 条收藏都已同步
- WHEN 打开「全部收藏」（或「最近新增」）
- THEN 页头显示「152 条收藏 · 已全部同步」

场景2: 已登录且部分待同步

- GIVEN 已登录，152 条中有 3 条待同步
- WHEN 打开「全部收藏」
- THEN 页头显示「152 条收藏 · 3 条待同步」

场景3: 未登录

- GIVEN 未登录，默认收藏库里有 20 条
- WHEN 打开「全部收藏」
- THEN 页头只显示「20 条收藏」（默认收藏库的条数），不出现任何同步相关文字

场景4: 收藏库为空

- GIVEN 收藏库一条收藏都没有
- WHEN 打开「全部收藏」
- THEN 沿用现有空态提示，不显示汇总行

## feat05: 账号卡显示服务器概览

「网络连接」页的账号卡上显示服务器上这个账号一共有多少条收藏，让用户不用猜服务器那边的家底。

场景1: 同步过至少一次

- GIVEN 已登录且完成过至少一次成功同步
- WHEN 打开「网络连接」
- THEN 账号卡显示「服务器上共 N 条收藏」，与现有「上次同步：<时间>」并排

场景2: 从未同步

- GIVEN 已登录但从未同步过
- WHEN 打开「网络连接」
- THEN 账号卡不显示服务器条数一行（只有「上次同步：尚未同步」）

场景3: 服务器暂时连不上

- GIVEN 上次同步成功时服务器有 152 条，当前服务器无法访问
- WHEN 打开「网络连接」
- THEN 服务器条数仍显示 152（最近一次成功同步时的值），不报错、不清空

## feat06: 按「待同步」筛选

用户能一键筛出还没同步上去的收藏，定位「哪些东西只在本机、服务器上还没有」。

场景1: 筛出待同步

- GIVEN 已登录，有 3 条待同步的收藏
- WHEN 点击筛选区的「待同步」入口
- THEN 列表只显示这 3 条，标题显示「筛选结果 · 3 条命中」，并可一键清除筛选回到全部

场景2: 全部已同步

- GIVEN 已登录，没有任何待同步的收藏
- WHEN 点击「待同步」
- THEN 显示空态「没有待同步的收藏，一切都已在服务器上」

场景3: 未登录时无此入口

- GIVEN 未登录
- WHEN 查看筛选区
- THEN 不显示「待同步」入口

## feat07: 手动创建快照存档

用户一键把当前整库（全部收藏，含四维属性与收藏理由，加四个分类维度的取值清单）存成一份带时间的快照，归到当前登录账号名下。View 上线后一并纳入快照内容。

场景1: 正常存档

- GIVEN 已登录，收藏库有 152 条
- WHEN 在「网络连接」页点击「立即存档」
- THEN 按钮变为「存档中…」并禁用，完成后提示「已存档 152 条收藏」，快照列表出现一条新记录，含存档时间与条数

场景2: 未登录

- GIVEN 未登录
- WHEN 查看「网络连接」页
- THEN 「立即存档」按钮不可用，旁边提示「登录后才能存档」

场景3: 存档失败

- GIVEN 已登录但服务器无法访问
- WHEN 点击「立即存档」
- THEN 提示「存档失败，请稍后再试」，快照列表不新增记录

场景4: 空库也允许存档

- GIVEN 已登录，收藏库为空
- WHEN 点击「立即存档」
- THEN 存档成功，记录显示「0 条」

场景5: 存档中不可重复触发

- GIVEN 一份快照正在保存中
- WHEN 再次点击「立即存档」
- THEN 按钮保持禁用，最终只产生一份新快照

## feat08: 查看与管理快照列表

用户能看到当前账号名下的全部快照，并可删除不需要的；快照严格按账号隔离。

场景1: 查看列表

- GIVEN 当前账号有 3 份快照
- WHEN 打开「网络连接」页的快照区
- THEN 按存档时间从新到旧排列，每份显示存档时间、收藏条数，以及「恢复」「删除」操作

场景2: 只看当前账号的快照

- GIVEN 同一服务器上账号 A 和账号 B 都存过快照
- WHEN 登录账号 A 查看快照区
- THEN 只显示 A 的快照；切换登录 B 后只显示 B 的

场景3: 删除一份快照

- GIVEN 快照列表中有多份快照
- WHEN 点击某份的「删除」并确认
- THEN 该份从列表消失，收藏库本身不受任何影响

场景4: 数量上限自动淘汰

- GIVEN 当前账号已有 10 份快照（上限）
- WHEN 第 11 份存档成功
- THEN 最旧的一份自动被淘汰，列表保持 10 份

场景5: 未登录

- GIVEN 未登录
- WHEN 打开「网络连接」页
- THEN 不显示快照区

场景6: 列表拉取失败

- GIVEN 已登录，但服务器不可达或拉取快照列表失败
- WHEN 打开「网络连接」页的快照区
- THEN 显式提示「快照列表拉取失败，请检查服务器连接。」，头部份数显示「列表拉取失败」；绝不把失败伪装成「还没有快照」；失败期间每分钟自动重试一次，服务器恢复后列表自行出现，无需重开页面

## feat09: 从快照恢复收藏库

用户能把本机收藏库整库恢复到某份快照时的样子，作为误操作或数据丢失后的兜底。

场景1: 正常恢复

- GIVEN 当前账号有一份 152 条的快照，本机现在有 160 条
- WHEN 点击该快照的「恢复」
- THEN 弹出确认框，明确说明「本机收藏库将被替换为该快照的内容，快照时间之后新增的收藏会被移除，且这个变化会照常同步到服务器」
- WHEN 用户点击「确认恢复」
- THEN 本机收藏列表与分类维度取值都变回快照中的内容（152 条），提示「已恢复至 <快照时间> 的存档」

场景2: 恢复后快照保留

- GIVEN 用户刚从快照 S 恢复成功
- WHEN 查看快照列表
- THEN S 仍在列表中，可以再次恢复

场景3: 恢复失败不动原库

- GIVEN 用户点击「确认恢复」后，读取快照内容失败（如服务器连接中断）
- WHEN 恢复失败
- THEN 提示「恢复失败，收藏库保持恢复前的样子」，本机内容无任何变化
