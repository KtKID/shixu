# 收藏当前页面（Capture 面板 · 保存并关闭 Tab）

让用户在看到值得留住的页面时，一键把它收进个人收藏库并安心关掉标签页：打开面板 →（可选）写一句「为什么收藏」、点几下分类 → 「保存并关闭 Tab」。收藏不要求当场整理，没填的内容以后随时可补。视觉与交互基准：`docs/assets/popup.html`（前端由他人依据本 spec 与协议实现）。

范围边界：收藏内容先进入用户的本地收藏库；与自建服务器的同步、四维筛选、动态视图、AI 摘要与分类建议均不在本 spec。全部从用户可感知的角度描述。

## feat01: 打开收藏面板

用户点击扩展图标或按快捷键，弹出「拾绪 · 收藏」面板，对当前标签页发起一次收藏。

场景1: 点击图标打开

- GIVEN 当前标签页是一个普通网页
- WHEN 用户点击浏览器工具栏的扩展图标
- THEN 弹出收藏面板，显示当前页面信息，光标停在「为什么收藏？」输入框

场景2: 快捷键打开

- GIVEN 当前标签页是一个普通网页
- WHEN 用户按下快捷键（macOS 为 ⌘⇧S，其他平台为 Ctrl+Shift+S）
- THEN 弹出与场景1相同的收藏面板

场景3: 快捷键未生效

- GIVEN 快捷键被其他扩展占用或浏览器未分配
- WHEN 用户在浏览器的「扩展快捷键」管理页为本扩展手动指定快捷键
- THEN 指定后快捷键可正常唤起面板；在此之前点击图标仍可使用全部功能

场景4: 在不可收藏的页面上打开

- GIVEN 当前标签页是浏览器内部页面（地址以 chrome://、about: 等开头）、本地文件页或扩展自身页面
- WHEN 用户打开面板
- THEN 面板显示「此页面无法收藏」，保存按钮不可点击（详见 feat02 场景2）

## feat02: 查看要收藏的页面信息

面板顶部只读展示被收藏页面的标题与地址，让用户确认收的是哪一页。

场景1: 正常展示

- WHEN 面板打开
- THEN 显示页面标题（最多两行，超出截断）与地址（过长时截断），左侧为首字母色块（不向外部服务请求网站图标）

场景2: 不可收藏的页面

- GIVEN 当前页面不是普通网页（浏览器内部页面、本地文件页、扩展自身页面）
- WHEN 面板打开
- THEN 显示「此页面无法收藏」，两个保存按钮都不可点击，理由输入与分类点选不可用

## feat03: 写一句话收藏理由

用户可以（但不必须）写一句「为什么收藏」；这句话不是文章摘要，而是当时为什么觉得它值得留下，是将来找回这条收藏最重要的线索，并参与搜索。

场景1: 输入理由

- WHEN 用户在「为什么收藏？」输入框打字
- THEN 可输入任意文字（可换行），可留空不写；标签旁提示「可选，但这句话以后最管用」

场景2: 回车保存并关闭

- GIVEN 光标在理由输入框
- WHEN 按下 Enter
- THEN 等同于点击「保存并关闭 Tab」（见 feat05）

场景3: 输入法组字中的回车

- GIVEN 用户正在用输入法组字（候选词尚未上屏）
- WHEN 按下 Enter
- THEN 仅确认候选词上屏，不触发保存

场景4: 换行

- GIVEN 光标在理由输入框
- WHEN 按下 Shift+Enter
- THEN 在理由内换一行，不触发保存

场景5: Esc 放弃

- GIVEN 面板已打开（可能已输入部分理由）
- WHEN 按下 Esc
- THEN 面板关闭，本次不做任何保存，已输入的草稿丢弃

## feat04: 点选四维分类

用户可以在面板里顺手点选这条收藏的分类属性；全部可选、不点也能保存。取值集合来自「设置」页，面板里只点选、不管理。

场景1: 多选维度点选（主题 / 形态 / 用途）

- GIVEN 面板展示「主题 · 它讲什么？」「形态 · 它是什么？」「用途 · 我拿它干什么？」三组取值
- WHEN 用户点击某个取值
- THEN 该取值变为选中态，再点一次取消；同一维度可同时选中多个

场景2: 状态单选

- GIVEN 「状态 · 我处理到哪了？」一组取值，默认选中「Inbox」
- WHEN 用户点击另一个状态
- THEN 仅最新点击的处于选中态，此前的自动取消

场景3: 取值集合与设置共享

- WHEN 面板渲染四组取值
- THEN 展示的即与「设置」页共享的同一套取值：在设置页新增/删除的取值，面板下次打开即呈现；面板内也可就地新增与删除取值（见 feat08），但不能改名

场景4: 完全不点直接保存

- WHEN 用户不点任何分类（状态保持默认「Inbox」）直接保存
- THEN 保存成功，这条收藏分类为主题空、形态空、用途空、状态 Inbox，之后随时可补

## feat05: 保存（保存并关闭 Tab / 仅保存）

把当前页面收进收藏库：核心动作为「保存并关闭 Tab」——看到、留下、安心关掉；想留着页面继续看时用「仅保存」。

场景1: 保存并关闭 Tab

- GIVEN 面板处于可保存状态
- WHEN 用户点击「保存并关闭 Tab」（或理由输入框内按 Enter）
- THEN 显示「✓ 已存入 Inbox，Tab 即将关闭」，随后该标签页关闭、面板关闭；这条收藏出现在库里（新收藏或更新已有条目，见 feat06）

场景2: 仅保存

- GIVEN 面板处于可保存状态
- WHEN 用户点击「仅保存」
- THEN 显示「✓ 已存入 Inbox」，面板关闭，标签页保留不动

场景3: 固定的标签页

- GIVEN 被收藏的标签页被用户固定（pinned）
- WHEN 用户保存并关闭 Tab
- THEN 保存成功，显示「✓ 已保存；固定标签页未关闭」，面板关闭，标签页保留不动

场景4: 窗口最后一个标签页

- GIVEN 该窗口只剩这一个标签页
- WHEN 用户保存并关闭 Tab
- THEN 保存成功，标签页随窗口一起关闭

场景5: 目标标签页已被关闭

- GIVEN 面板打开期间，被收藏的标签页已被用户从别处关闭
- WHEN 用户仍点击保存
- THEN 保存照常完成，不再执行关标签页，面板关闭

场景6: 保存过程中的重复点击

- GIVEN 保存正在进行
- WHEN 用户再次点击任一保存按钮
- THEN 忽略重复点击，不会产生重复保存

## feat06: 重复收藏同一页面

同一页面（忽略地址中跟踪参数等差异后视为同一页）在库里只存一条；再次收藏是更新，不是新增。

场景1: 打开面板发现已收藏过

- GIVEN 该页面已在收藏库中
- WHEN 用户打开收藏面板
- THEN 显示「已收藏过 · 保存将更新」提示；理由输入框与分类点选按库里已有内容预填（状态选中其当前状态）

场景2: 保存为更新

- GIVEN 面板处于「已收藏过 · 保存将更新」状态
- WHEN 用户保存（保存并关闭 Tab 或仅保存皆可）
- THEN 库里不新增条目，已有那条被更新：页面标题刷新为当前标题、修改时间更新、理由与四维分类按面板当前内容覆盖保存

场景3: 清空理由后保存

- GIVEN 该页面在库中已有理由
- WHEN 用户在面板清空理由后保存
- THEN 该条收藏的理由被清为空（覆盖语义，不保留旧值）

场景4: 曾被删除的页面

- GIVEN 该页面以前收藏过、后来被删除
- WHEN 用户再次收藏
- THEN 仍是同一条（复活），不产生新条目；创建时间保留最初那条的，修改时间更新为本次

## feat07: 面板顶栏的库计数

顶栏显示库规模，让用户随手知道自己攒了多少条收藏。

场景1: 查看库规模

- WHEN 面板渲染完成
- THEN 顶栏在「已收藏」入口左侧显示「收藏N条」，N 为库中实际收藏数（含收藏与导入的全部）

场景2: 库还是空的

- GIVEN 用户从未导入或收藏过任何书签
- WHEN 面板渲染完成
- THEN 显示「收藏0条」

## feat08: 面板内就地增删维度取值

用户在收藏时想到一个更贴切的分类词，不必跳去设置页：在维度卡片里直接新增取值并点选；误加的取值也可就地删除。增删与「设置」页操作的是同一套取值，两边永远一致。删除按钮平时不显示：点面板右上方的「修改」进入修改模式后才出现，避免日常点选时的视觉噪音与误触。

场景1: 就地新增取值

- GIVEN 用户已进入修改模式（见场景7）：每个维度卡片的底部有一条修改区（输入框 + 加号按钮），非修改模式下修改区不显示
- WHEN 用户在输入框里输入新取值后点击加号（或按 Enter）
- THEN 该取值立即出现在本维度的取值中，可直接点选；输入框清空、光标留在输入框里，方便连续添加

场景2: 新增校验

- WHEN 用户提交新取值
- THEN 纯空白的输入不添加也不提示；与已有取值重复时提示「该取值已存在」；超过 30 字时提示「取值过长」；提示在再次输入时消失

场景3: 就地删除取值

- GIVEN 用户已点面板右上方「修改」进入修改模式（按钮变为「完成」，见场景7），每个已有取值右侧出现「×」删除按钮
- WHEN 用户点击某个取值的「×」
- THEN 该取值从本维度消失（设置页里同步消失）；若该取值正处于选中态，选中同时取消；删除的是当前选中的状态时，状态回退为「Inbox」；删除取值不影响任何已保存的收藏

场景4: 受保护的默认状态

- GIVEN 修改模式下，「Inbox」是系统默认状态
- WHEN 用户点击「Inbox」的「×」
- THEN 提示「默认状态不可删除」，取值保留

场景5: 维度卡片布局

- WHEN 面板渲染维度卡片
- THEN 修改模式下卡片自上而下分为三段：顶部标题（维度名、引导问题、单选/多选标注）、中部取值区（随取值数量自动伸缩高度）、底部修改区（输入框与加号横向贴齐卡片左右边缘）；非修改模式下只有前两段（无底部修改区）；面板整体的左右宽度不因本功能改变

场景6: 不可收藏页面

- GIVEN 当前页面不可收藏
- WHEN 面板渲染维度卡片
- THEN 新增与删除入口与点选一并不可用（「修改」切换本身可用，切换出的「×」仍处于禁用）

场景7: 修改模式的进出与重开复位

- WHEN 面板打开
- THEN 右上方显示「修改」按钮，取值上没有任何「×」删除按钮，维度卡片也没有底部修改区（默认非修改模式）
- WHEN 用户点击「修改」
- THEN 该按钮变为「完成」，取值右侧出现「×」删除按钮，每个维度卡片底部出现修改区（输入框与加号）
- WHEN 用户点击「完成」
- THEN 按钮变回「修改」，「×」与修改区全部隐藏，增删产生的错误提示一并清除
- GIVEN 面板处于修改模式（或任何状态）
- WHEN 用户以任何方式关闭面板后重新打开
- THEN 面板回到默认非修改模式，不延续上次的状态

场景8: 面板高度自适应内容

- WHEN 面板渲染
- THEN 面板高度跟随内容自适应：不设固定高度、不做内部滚动区；默认非修改模式下内容一屏放下、无任何滚动
- GIVEN 内容超出浏览器 popup 高度上限（Chrome 为 600px，如修改模式或取值较多时）
- WHEN 内容放不下
- THEN 按浏览器原生行为处理：面板高度停在上限、出现浏览器自身的滚动；扩展不另做滚动区域、不钉住局部区块
