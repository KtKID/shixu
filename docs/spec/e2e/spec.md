# 端到端自动化验证（e2e）

给作者一个「一键跑通产品主链路」的最终验收手段：在真实浏览器里装载真实扩展、连一个一次性的本地服务器，把「导入 → 登录 → 同步 → 快照存档 → 恢复 → 登出」整条链走一遍。组件测试与协议冒烟都是局部的，这一层补上「装进真浏览器后到底好不好使」的答案。每轮验证环境全新、跑完自动清理，不碰日常开发的数据与正在运行的服务。本 spec 只描述运行验证的人可感知的行为，不约束用什么测试工具实现。

## feat01: 一条命令跑完端到端验证

运行者执行一条命令就能完成扩展准备、环境搭建、逐场景验证与结果汇总，全程无需手动干预。

场景1: 全部通过

- GIVEN 环境就绪（测试浏览器已安装）
- WHEN 运行者执行端到端验证命令
- THEN 验证自动把扩展准备成可装载的最新版本、启动一次性服务器、装载扩展并逐场景执行，结束后显示全部通过的场景数与总耗时

场景2: 某个场景失败

- GIVEN 端到端验证正在运行
- WHEN 某个场景验证失败
- THEN 报告指明失败的场景与卡住的一步（期望什么、实际看到什么），其余场景继续执行，最后汇总一份失败清单

场景3: 缺少测试浏览器

- GIVEN 本机从未安装过测试浏览器
- WHEN 运行者首次执行验证命令
- THEN 给出明确的一次性安装指引，按指引安装后重跑即可，不需要改任何配置

场景4: 测试环境已存在

- GIVEN 本机已有可用的测试工具与测试浏览器
- WHEN 运行者执行验证命令
- THEN 检查确认后直接复用现有安装，不重新下载、不重复安装（任何安装动作前都必须先检查是否已存在）

## feat02: 全新的隔离运行环境

每轮验证都在全新的环境里进行，跑完自动清理，与日常开发数据互不影响。

场景1: 每轮全新浏览器档案

- GIVEN 上一轮验证登录过账号、收藏过书签
- WHEN 重新运行一轮验证
- THEN 扩展里看不到上一轮的任何登录态、收藏与历史服务器，一切从空开始

场景2: 每轮全新服务器数据

- GIVEN 上一轮验证在服务器上注册过账号、同步过收藏
- WHEN 重新运行一轮验证
- THEN 服务器从空库开始，上一轮的数据不复存在

场景3: 结束自动清理

- GIVEN 一轮验证全部通过
- WHEN 运行者查看磁盘与运行中的进程
- THEN 验证用的浏览器档案、服务器数据、临时文件都已删除；日常开发的收藏数据与正在运行的日常服务器不受任何影响（失败轮次保留现场，见 feat09）

场景4: 端口不冲突

- GIVEN 日常开发服务器正在运行
- WHEN 运行端到端验证
- THEN 验证自动选用空闲端口，两者互不干扰，验证结果不受影响

## feat03: 真实浏览器装载扩展

验证开始时把扩展装载进真实浏览器，装载成功是后续所有场景的前提。

场景1: 装载成功

- GIVEN 环境就绪
- WHEN 验证启动浏览器并装载扩展
- THEN 扩展后台就绪，扩展主页与弹窗都能正常打开

场景2: 装载失败

- GIVEN 浏览器无法装载扩展（如浏览器文件缺失、版本不支持）
- WHEN 验证启动
- THEN 明确报错说明装载失败与原因，不产出「通过」的结果

## feat04: 导入链路验证

验证「浏览器书签 → 导入 → 收藏库」这条路在真实浏览器里走得通。

场景1: 导入预置书签

- GIVEN 浏览器里预置了 3 条书签，扩展未登录（使用默认收藏库）
- WHEN 运行者在主页导入区勾选这 3 条并导入
- THEN 收藏页出现这 3 条，条数统计为 3，每条状态为 Inbox

场景2: 重复导入不重复

- GIVEN 上一场景的 3 条已导入
- WHEN 再次导入其中同一条
- THEN 收藏库仍只有这一份，条数不变

## feat05: 登录与同步链路验证

验证「注册登录 → 收藏 → 同步 → 同步状态呈现」在真实链路上正确。

场景1: 注册并登录

- GIVEN 服务器可达，扩展在默认收藏库（库里有 3 条）
- WHEN 运行者在「网络连接」注册一个新账号并登录
- THEN 界面切到该账号的空收藏库，默认库的 3 条不显示（原样留在默认库）

场景2: 收藏并同步

- GIVEN 已登录且账号库为空
- WHEN 运行者导入 1 条并点击「同步收藏」
- THEN 这条卡片的云朵显示已同步，页头显示「1 条收藏 · 已全部同步」，账号卡显示「服务器上共 1 条收藏」

场景3: 待同步可见可筛

- GIVEN 全部已同步（1 条）之后，又导入了 1 条且未同步
- WHEN 查看页头并点击「待同步」筛选
- THEN 页头显示「2 条收藏 · 1 条待同步」，列表只剩新导入的那条，标题显示筛选命中

场景4: 同步失败不误报

- GIVEN 存在待同步的收藏
- WHEN 服务器临时不可达时点击「同步收藏」，随后服务器恢复并再次同步
- THEN 失败期间云朵保持待同步样式不误报；服务器恢复后同步成功，云朵翻回已同步

## feat06: 快照存档与恢复验证

验证「整库存档 → 整库恢复」这条兜底路在真实链路上正确。

场景1: 立即存档

- GIVEN 已登录，账号库有 2 条收藏
- WHEN 运行者点击「立即存档」
- THEN 快照列表出现一条新记录，显示存档时间与「2 条」

场景2: 恢复到快照

- GIVEN 存档后库里又导入 1 条（共 3 条）
- WHEN 运行者对快照点「恢复」并在确认框确认
- THEN 收藏列表回到快照时的 2 条，显示「已恢复至 <快照时间> 的存档」

场景3: 快照保留可再次恢复

- GIVEN 刚完成一次恢复
- WHEN 查看快照列表并对同一份再点「恢复」
- THEN 该快照仍在列表中，恢复再次成功

## feat07: 多库与登出验证

验证「换库不混数据、登出回默认库」在真实浏览器里正确。

场景1: 登出回默认库

- GIVEN 已登录账号，默认收藏库里有导入的 3 条
- WHEN 运行者退出登录
- THEN 界面回到默认收藏库，3 条原样都在，界面上不显示任何同步信息

场景2: 未登录无同步元素

- GIVEN 未登录任何账号
- WHEN 浏览收藏页与筛选区
- THEN 卡片上没有云朵标记，页头只有「N 条收藏」，筛选区没有「待同步」入口，「网络连接」里没有快照区、存档按钮不可用

## feat08: 收藏面板真链路验证

验证「看到页面 → 唤起面板 → 保存并关闭 Tab」这条核心动作在真实浏览器里走得通。

场景1: 从普通网页唤起面板

- GIVEN 打开一个普通网页
- WHEN 运行者唤起收藏面板（点扩展图标与快捷键两种产品入口等效，验证任选其一）
- THEN 面板显示该网页的地址与标题，光标停在「为什么收藏？」输入框

场景2: 保存并关闭 Tab

- GIVEN 收藏面板已唤起，并填了一句收藏理由
- WHEN 点击「保存并关闭 Tab」
- THEN 面板关闭、原网页标签页被关闭，该页面出现在收藏库里（含所填理由与 Inbox 状态）

场景3: 弹窗库计数

- GIVEN 库里已有若干收藏
- WHEN 打开扩展弹窗
- THEN 显示当前收藏库的条数计数

场景4: 不可收藏页面

- GIVEN 当前标签页是浏览器内部页面
- WHEN 唤起收藏面板
- THEN 面板显示「此页面无法收藏」，保存按钮不可点击

## feat09: 失败现场可复查

验证失败时留下现场，让运行者能人工复现与排查。

场景1: 失败留现场

- GIVEN 某场景验证失败
- WHEN 运行者查看验证输出
- THEN 找到该失败步骤的页面截图与现场数据目录路径，能按路径打开当时的浏览器档案与服务器数据排查

场景2: 全绿不留现场

- GIVEN 一轮验证全部通过
- WHEN 运行者查看磁盘
- THEN 不遗留截图与现场数据，只有一份结果摘要
