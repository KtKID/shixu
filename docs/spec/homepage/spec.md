# 插件主页（左侧导航 · 最近新增 · 网络连接 · 维度 · 导入书签）

以「已收藏主页」作为进入这个插件的主页：一个独立的整页，左侧是导航列表，右侧是内容区。默认进入第一个导航项「最近新增」，快速看到最近收藏；「全部收藏」浏览收藏库的全部书签并按四个维度筛选、按关键词搜索；「网络连接」「分类维度」「导入已有书签」作为左侧导航的其余条目，把原来散落在设置页和导入器里的功能收进同一个主页。

视觉与交互参考 `docs/assets/homepage.html`（另参考 `docs/assets/settings.html`、`docs/assets/popup.html`）：原型文件**只作参考**，实现全新开发，不修改、不直接复用原型文件。与原型的差异点均为有意设计，共三处：状态是单选（原型误做成了可多选）、主题维度提供「全部满足」切换（原型缺失）、页面内容居中（原型为紧凑靠左）。

范围边界：左侧导航中「网络连接」（服务器、账号）与「分类维度」两个条目内的具体行为沿用《设置页面》spec（`docs/spec/settings/spec.md`），本 spec 不重复定义；书签与服务器的同步推拉、动态视图的保存、回收站、主动提示（Resurface）、接管浏览器新标签页均不在本 spec。收藏库数据全部来自本地，未登录、服务器不可用时本 spec 的所有功能照常可用。

## feat01: 从收藏面板进入插件主页

用户在收藏面板顶部点「已收藏」或「设置」按钮，整页打开插件主页。

场景1: 点击已收藏按钮

- GIVEN 收藏面板已打开（点扩展图标或快捷键唤起）
- WHEN 用户点击面板顶部的「已收藏」按钮
- THEN 在新标签页整页打开插件主页，落在默认的第一个导航项「最近新增」；收藏面板关闭，本次未保存的理由输入与分类点选不保留、也不自动保存

场景2: 点击设置按钮

- GIVEN 收藏面板已打开
- WHEN 用户点击面板顶部的「设置」按钮
- THEN 同样打开插件主页，但落在左侧导航的「网络连接」条目；收藏面板同样关闭，未保存的输入不保留、不自动保存

场景3: 从浏览器扩展管理页进入

- GIVEN 用户在浏览器的扩展管理页
- WHEN 用户点击本扩展的「扩展选项」入口
- THEN 整页打开插件主页，落在「最近新增」（原独立的设置页与书签导入器页面不再单独存在，功能都在主页左侧导航里）

场景4: 未登录时打开

- GIVEN 用户从未连接或登录过任何服务器
- WHEN 用户打开插件主页
- THEN 主页正常打开并显示本地收藏库内容；连接服务器只影响以后的同步，不影响本页使用

场景5: 导入入口收敛

- GIVEN 本次改版前，收藏面板底部有「打开导入器」按钮
- WHEN 改版后用户查看收藏面板
- THEN 该按钮不再出现（导入入口统一为主页左侧导航的「导入已有书签」条目），库计数改在顶栏「已收藏」入口左侧显示「收藏N条」（原底部计数条移除）

## feat02: 主页左侧导航

主页左侧是导航列表，右侧是内容区；导航条目即各功能分区。

场景1: 导航结构

- GIVEN 用户打开插件主页
- THEN 左侧导航从上到下依次为：「最近新增」（默认选中）、「全部收藏」、「网络连接」、「分类维度」、「导入已有书签」；其中「全部收藏」见 feat07，「网络连接」内是服务器地址/端口、测试连接、历史服务器与账号登录，「分类维度」内是四个维度的取值管理（两者行为沿用《设置页面》spec），「导入已有书签」见 feat03

场景2: 切换导航不丢输入

- GIVEN 用户在「网络连接」里填了服务器地址但还没测试
- WHEN 用户切到「分类维度」再切回「网络连接」
- THEN 已填的服务器地址仍在（同一次打开内切换不丢失；跨次打开不要求保留）

场景3: 预留导航项不出现

- GIVEN 设计稿侧栏里还有「视图」「回收站」等条目
- WHEN 用户查看左侧导航
- THEN 本阶段不显示这些条目（待对应功能落地后再加入，导航顺序在其后追加）

场景4: 内容区居中

- GIVEN 用户打开插件主页（任意导航条目下）
- WHEN 用户查看右侧内容区
- THEN 内容在内容区内**水平居中**展示（有最大宽度，窗口很宽时内容不摊满、不贴左），与参考原型的紧凑靠左布局不同；左侧导航栏固定在页面左缘，宽度不随窗口拉伸

## feat03: 在主页导入已有书签

用户把浏览器里已有的书签搜索、勾选后导入收藏库；即现在导入器的能力搬进主页的导航条目，用户可感知的行为不变。

场景1: 搜索并导入

- GIVEN 用户的浏览器里有若干书签（分布在多个文件夹）
- WHEN 用户打开「导入已有书签」条目，输入关键词过滤，勾选若干条后点导入
- THEN 勾选的书签进入本地收藏库，状态默认为 Inbox，提示导入成功；这些书签随后出现在「最近新增」

场景2: 重复导入同一条

- GIVEN 收藏库里已有某网址的书签
- WHEN 用户再次勾选同一网址（即使本次显示的标题、来源文件夹不同）导入
- THEN 系统识别为同一条收藏（网址先做规范化再去重），提示「已收藏过」，不产生第二条记录

场景3: 浏览器没有任何书签

- GIVEN 用户的浏览器书签为空
- WHEN 用户打开「导入已有书签」条目
- THEN 显示「浏览器中没有可导入的书签」的空状态，不显示搜索框和导入按钮

场景4: 未登录时导入

- GIVEN 用户未登录任何服务器
- WHEN 用户导入书签
- THEN 书签保存在本地收藏库并立即可在「最近新增」查看；登录后的上传同步不在本 spec

## feat04: 最近新增视图

主页默认视图：按收藏时间从新到旧浏览收藏库。

场景1: 默认展示

- GIVEN 收藏库里有若干条收藏
- WHEN 用户打开主页（或从其他导航条目切回「最近新增」）
- THEN 标题为「最近添加」，按收藏时间从新到旧展示最近 3 条，下方提示「选择上方标签开始按维度筛选」；未选择任何筛选时不展开全部列表

场景2: 每条收藏的展示内容

- GIVEN 收藏库里有带完整信息的收藏
- WHEN 用户浏览列表
- THEN 每条收藏以卡片展示：首字母色块、标题、来源域名、收藏时间（如「2 天前」）、收藏理由（Context，一句话）、分类标签（主题、形态的已选取值与状态取值）；理由为空的收藏不显示理由区域

场景3: 空收藏库

- GIVEN 收藏库为空（全新安装且未导入）
- WHEN 用户打开「最近新增」
- THEN 显示空状态提示，并提供去「导入已有书签」条目的引导入口

场景4: 打开原网页

- GIVEN 列表中展示着若干收藏卡片
- WHEN 用户点击某张卡片
- THEN 在新标签页打开该收藏的原网址

## feat05: 按四个维度筛选

用户在「最近新增」视图用主题、形态、用途、状态四个维度组合筛选收藏。规则：同一维度内多选取「或」（任一满足即命中），不同维度之间取「且」（都要满足）；状态维度只能单选；主题维度可切换为「全部满足」。候选标签来自用户在「分类维度」里自定义的各维度取值。

场景1: 同维度多选命中任一

- GIVEN 库里有书签 A（主题=AI）和书签 B（主题=世界模型）
- WHEN 用户在主题维度同时选中「AI」和「世界模型」
- THEN A、B 都命中；标题变为「筛选结果 · 2 条命中」，结果按收藏时间从新到旧排列

场景2: 跨维度都要满足

- GIVEN 库里有书签 A（主题=AI，形态=论文）和书签 C（主题=AI，形态=GitHub 仓库）
- WHEN 用户选中主题「AI」和形态「论文」
- THEN 只有 A 命中；每个维度的选择共同生效（维度间取「且」）

场景3: 状态单选

- GIVEN 用户已选中状态「Reading」
- WHEN 用户再点状态「Done」
- THEN 仅保留「Done」（点选即替换，不能同时选中两个状态）；再点一次「Done」则取消该条件

场景4: 主题「全部满足」切换

- GIVEN 用户在主题维度选中了「AI」和「世界模型」，当前为默认的「满足任一」
- WHEN 用户把主题维度切换为「全部满足」
- THEN 只有同时标有这两个主题的收藏命中；切回「满足任一」则标有其中任意一个即命中；此切换只作用于主题维度

场景5: 候选计数随其他条件变化

- GIVEN 用户已选中形态「论文」
- WHEN 用户查看主题维度的候选标签
- THEN 每个主题标签旁的数字表示「在形态=论文的前提下，标有该主题的收藏条数」（按其他维度的已选条件动态计算，不含本维度已选项的影响）；已选中的标签永远显示，计数为 0 的候选也仍然显示

场景6: 取消单个条件与清除全部

- GIVEN 用户已选中主题「AI」和形态「论文」
- WHEN 用户再点一次「AI」标签
- THEN 仅取消「AI」这一条件，形态「论文」保持选中，结果随之更新；当存在任一筛选时，右上角显示「清除全部筛选」，点击后回到默认的「最近添加」视图

场景7: 没有命中

- GIVEN 用户的筛选组合下没有任何收藏满足
- WHEN 结果刷新
- THEN 显示「没有同时满足这些条件的收藏，试试减少一个维度。」；已选条件保持可见、可撤销，不自动清除用户的选择

## feat06: 搜索收藏

用户用关键词在收藏库里查找收藏，标题、来源域名、收藏理由（Context）都参与搜索。

场景1: 搜到结果

- GIVEN 库里有收藏的理由写着「重点看 action → next state 的设计」
- WHEN 用户在搜索框输入「action」
- THEN 该收藏出现在结果中；标题或域名包含关键词的收藏同样命中；结果按收藏时间从新到旧排列，并显示命中条数

场景2: 没有匹配

- GIVEN 库里没有任何内容包含「量子」
- WHEN 用户搜索「量子」
- THEN 显示「没有找到相关收藏」的空状态，不显示列表

场景3: 与筛选叠加

- GIVEN 用户已选中形态「论文」，再在搜索框输入「世界模型」
- WHEN 搜索生效
- THEN 只显示既满足筛选条件、又匹配关键词的收藏（两者取「且」）；清空搜索框则回到仅按筛选显示

场景4: 快捷键聚焦

- GIVEN 主页已打开，光标不在搜索框
- WHEN 用户按下 ⌘K（Windows/Linux 为 Ctrl+K）
- THEN 光标聚焦到搜索框，可直接输入

## feat07: 全部收藏视图

左侧导航「全部收藏」条目：不截取地浏览收藏库的全部收藏；筛选与搜索能力与「最近新增」完全一致（feat05/feat06 的规则原样适用）。

场景1: 默认展示全部

- GIVEN 收藏库里有超过 3 条收藏
- WHEN 用户打开「全部收藏」条目（或地址 hash 指定该条目）
- THEN 标题为「全部收藏」，按收藏时间从新到旧展示**全部**收藏，不截取最近 3 条，也不显示「只显示最近 3 条」的提示

场景2: 筛选与搜索行为一致

- GIVEN 用户在「全部收藏」里选择维度条件或输入关键词
- THEN 行为与「最近新增」一致：标题切换为「筛选结果 · N 条命中」、存在筛选时显示「清除全部筛选」、没有命中显示对应空态文案、搜索与筛选取「且」叠加

场景3: 空收藏库

- GIVEN 收藏库为空
- WHEN 用户打开「全部收藏」
- THEN 与「最近新增」一致显示空状态提示，并提供去「导入已有书签」的引导入口
